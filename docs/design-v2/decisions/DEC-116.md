### The scribe's notes

- the ruling, taken together: a free GitHub organization named `kokonada`, with the policy at `https://kokonada.github.io/privacy/` (the numbering note at the end of the rulings file).
- the organization: it did not exist when first checked on 2026-10-01 (the GitHub API returned 404 for `orgs/kokonada` and for `users/kokonada`). The owner then created it. On 2026-10-01 the GitHub API shows login `kokonada`, type Organization, created 2026-10-01T08:47:53Z, 0 public repositories, and the owner's membership with role admin and state active; the orchestrator checked it, and the scribe checked it again. So the name in the URL is registered to the owner, which is the compliance-auditor's MUST (h): "The name in the URL is registered before the constant is written." The site's repository and the page itself are still to come (`DAN-015`, with counsel's text). The brief also lets no build that carries the address reach anyone but the owner until `DAN-015` closes (its first answer up front).
- what this option costs, in the compliance-auditor's words (OD-1, option B, quoted below): Play and Health Connect are fine; "It can never be OAuth-verified (R18: a DNS Domain property)"; and "Once builds are distributed it can never move". OAuth verification, which the brief ties to `youtube.readonly` and brand verification, needs an owned domain verified in DNS, `DAN-007`; this ruling leaves that row where it is.
- the visitor logs (the regulatory-researcher's Table 4, quoted below): GitHub Pages logs every visitor's IP address, and the host's role for those logs must be known before the policy is written.
