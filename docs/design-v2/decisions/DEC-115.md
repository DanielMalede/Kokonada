### hx2-r3-compliance.md · Handback 3 · line 78; lines 108–117

I accept F1's substance and the merged fallback sentence. What is still owed is a narrower claim in two places. Both say that no production count at all can see an H1 failure, but the code shows one could. Only E3 step 5 is blind to it, which is how line 7 already puts it.

**The candidate count.** Its logic is sound for production today:
- Only the Spotify callback pairs a token with `musicProvider: 'spotify'` (`integrationsController.js:150-156`).
- The disconnect nulls both in one save (`:198-203`).
- A refresh writes only the token (`spotify.js:155-158`).

It has two limits:
- `musicProvider: null` also matches a document with no such field, so an account linked before the callback set `musicProvider` would be counted. This is UNVERIFIED: I could not read the field's history.
- A later YouTube connect or disconnect rewrites `musicProvider` (`:373`, `:417`) and could hide a write-back. YouTube is dormant in production.

If the owner adopts it, record it before merge as a baseline and again after E2; a rise after HX-2 is the H1 signal.
