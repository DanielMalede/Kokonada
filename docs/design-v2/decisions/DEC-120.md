### hx5-r1-regulatory.md · §3, MB-062: data minimisation and the declarations · lines 41–45 and 52

**3. MB-062: data minimisation and the declarations**
- **Facts:**
  - The app has no translations: only `res/values/strings.xml`, no `values-*` folder, no `.lproj`, no i18n library, and `CONSENT_SECTIONS` is hard-coded English. The consent text is English for every grant.
  - `android:supportsRtl="true"` (`AndroidManifest.xml:51`), so the device's language may mirror the layout. This is not verified on a device.
  - The region subtag has no bearing on the rendered sheet.

- **The wording problem holds whatever is stored.** Measured against the stated purpose ("the language it was given in"), a stored "he-IL" is inaccurate. REG-034 archives "in each language", and DEC-117's selected option reads "ואת השפה" ("and the language"), not the region. What to store is the owner's call (OQ2).

### hx5-r1-regulatory.md · R4, the server's shapes · lines 136–140

**R4 · NON-BLOCKING · Server shapes narrowed to what the client sends** (Art. 25(1)–(2)).
- `consent.js:66`: `/^[0-9A-Za-z][0-9A-Za-z .()+_-]{0,31}$/` → `/^[0-9]{1,4}(\.[0-9]{1,4}){0,3} \([0-9]{1,9}\)$/`
- `consent.js:67`, two options:
  - L1 (keep language and region): `/^[A-Za-z]{2,3}(-[A-Za-z0-9]{2,8}){0,3}$/` → `/^[a-z]{2,3}(-([A-Z]{2}|[0-9]{3}))?$/`
  - L2 (language only): → `/^[a-z]{2,3}$/`, and in `grantProvenance.ts`, `return region ? \`${lang}-${region.toUpperCase()}\` : lang;` → `return lang;`
