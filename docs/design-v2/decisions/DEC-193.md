- the scribe's English gloss of the question: The "GET SPOTIFY FREE" button when Spotify is not installed on the phone: on 30.9 you ruled that it opens the song's page on Spotify's website, and not the download page (DEC-112). ## Sources

- Spotify Design Guidelines, "Linking to Spotify": "If the app is not installed, the user should be directed to the app store so that they can install Spotify." and "If the Spotify app is not installed then the link should say, GET SPOTIFY FREE." https://developer.spotify.com/documentation/design. Quoted by the compliance-auditor in hx4 round 2 (2026-09-30, `DAN-041`) and in `CMP-008`'s amendment of 2026-09-30; CA307-15 read the live guidelines on 2026-11-25.
- Spotify Developer Policy II.4.2: "Metadata, cover art and Audio Preview Clips must be accompanied by a link back to the applicable album, content or playlist on the Spotify Service." https://developer.spotify.com/policy, as quoted in `CMP-008` (retrieved 2026-09-29; the Policy is "Effective as of 15 May, 2025", retrieved 2026-09-30).

## The scribe's notes

- **What it settles.**
  - When Spotify is not installed, GET SPOTIFY FREE opens Spotify's app-store listing:
    - on Android, `market://details?id=com.spotify.music` (the Play Store app), and on failure `https://play.google.com/store/apps/details?id=com.spotify.music`;
    - on iOS, `https://apps.apple.com/app/spotify-music-and-podcasts/id324684580`. iOS is frozen, so this branch has never run on a device.
  - Neither store URL carries a parameter.
  - The title and the cover art on the player screen link to the item's page, `https://open.spotify.com/<type>/<id>`, for Spotify content only.
  - It applies to the shipped player now (`MB-200`) and to the v2 player, P3 (`MB-202`).
  - The label stays "GET SPOTIFY FREE" (`CMP-009`; DEC-053 keeps it in English). OPEN SPOTIFY, the installed branch, is unchanged.
- **The pin it reverses** (the scribe's reading, not the owner's words: reversing DEC-112 reverses the test that records it).
  - `mobile/KokonadaHealth/src/experience/player/__tests__/SpotifyAttribution.test.tsx`, "not installed: pressing opens the same item's web page (contentUri), never a store or download page", is replaced by a test that the press opens the store listing and never the item's page.
  - `openSpotifyWebPage`'s own tests stay, because it now serves the title and the cover.
- **What it does not settle.**
  - `CMP-008` stays HALT until the device proof (`MB-201`; DEC-097, DEC-101). Its status line is the compliance-auditor's to re-issue.
  - `DAN-041`'s second choice, attribution in the web link (`utm_campaign`), and any store referrer. The build adds neither.
  - The installed branch's own fallback, when the app URI finds no handler (Spotify uninstalled after the install probe), still opens the item's page. The question did not ask about it.
