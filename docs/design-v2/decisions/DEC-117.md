## The question, as each source asked it (history)

### hx5-brief-regulatory.md · §0, what shipping it in HX-5 at consent v1 would close off · lines 19–24

What shipping it in HX-5 at consent v1 would close off:
- **B(ii) for the interval.** Every grant made after the link appears would be recorded exactly like the earlier v1 grants: a version number, the categories and a time. No build identifier exists (§1, F2). The record could not later show which grants were given with the link on screen. That cannot be repaired afterwards.
- **B(i) and D outright,** because the link would be live without a version bump.
- **C is not yet testable.** Under C the linked page is part of the information. That page is not hosted (DAN-015).

**Only Option O1 (§5, Table 1) leaves every reading open:** hold the sheet part of HX-5 for the v3 bump PR. Option O2 (ship it with the per-grant build record and an archive first) keeps A, B(ii) and C open but still closes B(i) and D. The placement itself can be reused unchanged in either case.

### hx5-brief-regulatory.md · §2, Reading B and B(i) · lines 126–131

Under B, grants given after the link appears must be distinguishable in the record.

**B(i) · Bump the version.**
- It trips the Garmin gate (F4): moving to v2 opens the Garmin lane for new grants.
- It re-prompts every grantor with "Your consent terms were updated" (F5). For a change that only adds a link, that sentence is untrue. By analogy, it is "Conflicting information" in EDPB 03/2022's terms (Annex I 4.6.1, which maps it to "Informed consent: Article 7 (2) in conjunction with Article 4 (11)").
- It pauses live heart rate for every wearable user.
