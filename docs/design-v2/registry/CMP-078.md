### CMP-078 · Prominent disclosure before sensitive access
- kind: OBLIGATION
- rule: Right before any runtime permission or sensitive collection (the Bluetooth heart-rate lane), an in-app disclosure appears in normal use. It describes the data and its use, is not bundled with unrelated notices, and needs an affirmative tap. Back, tapping away and Home never count as consent, and it never dismisses itself.
- source: Google Play User Data: the disclosure must "be within the app itself…", "be displayed in the normal usage of the app…", "describe the data being accessed or collected", "explain how the data will be used and/or shared", "require affirmative user action", "must not interpret navigation away from the disclosure (including tapping away or pressing the back or home button) as consent", "must not use auto-dismissing or expiring messages". https://support.google.com/googleplay/android-developer/answer/10144311 · retrieved 2026-09-29
- provider: Google Play
- applies to: P5, P6, F10 (ConsentChoicePair), Q3
- surfaces: PR #193 removed the boot prompt, and `requestBlePermissions` has no production caller. P6 builds the disclosure.
- verify at: CI — stateful-fake tests: Back gives no request, Continue gives exactly one. G12 — a recording.
- severity if broken: P0
