### CMP-045 · YouTube data is kept for 30 days at most
- kind: PROHIBITION
- rule: YouTube data the user authorised (liked videos, titles, channels, and taste derived from them) is kept for 30 calendar days at most, then deleted or refreshed.
- source: YouTube API Developer Policies III.E.4.c: "API Clients may store all other types of Authorized Data … for no longer than 30 calendar days". https://developers.google.com/youtube/terms/developer-policies · retrieved 2026-09-29 · Amended 2026-09-30: re-verified on the page "Last updated 2026-09-14 UTC". III.E.4.e: "In all cases, API Clients must use reasonable efforts to ensure that their stored API Data is consistent with the current data available through YouTube API Services." · retrieved 2026-09-30
- provider: YouTube
- applies to: backend, P8, server plumbing
- surfaces: `PlaylistSession.trackSummary` for tracks from YouTube (no TTL); `backend/app/models/UnclassifiedTrack.js:7-20` (no expiry, BE-034); the YouTube-derived fields `topArtists` and `topGenres` · Amended 2026-09-30: `ServeEvent.js:26`; `reclassify.worker.js:68` (`_promote`); `youtubeRetention.worker.js:20-21,77,92-98`: a 7-day grace past 30 days keeps YouTube rows up to 37 days, and III.E.4.c has no grace. Not dormant by configuration: `youtube.js` falls back to `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (set in production), and `YOUTUBE_REDIRECT_URI` was present until 2026-10-01, so the backend treated YouTube as configured. Sealed in code by DEC-122 (HX-3); production counts all zero at 2026-10-01T14:05Z (DAN-046).
- verify at: CI — TTL tests · Amended 2026-10-01: Disconnect half, under DEC-122: the seal tests and DAN-046 counts as in CMP-043; if P0b finds a past YouTube link, a strip of that account's session provider fields and a zero count after it. The `youtubeRetention` grace (BE-060) and `_promote` (BE-056) have nothing to apply to under DEC-122 and are prerequisites in ARCH-012.
