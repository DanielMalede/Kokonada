What I found on this screen

It isn't achromatic. Two elements carry the accent: the wave inside the wordmark rule (var(--accent)) and the 300px glow behind the mark (var(--accentfill)). Both resolve to #3A5CCC — the default I put in every board's base scope, which is also the undeclared blue you spotted on Profile's toggle and the Vault's withdraw button. My earlier sweep counted only var(--accent) and reported "1 use", so it under-reported this screen by one.

The brand mark's ring fails the non-text contrast floor. It's drawn in --line2, which composites to 1.85 : 1 light and 2.64 : 1 dark against a 3 : 1 requirement. The ring is the outer half of the mark, so the identity is half-invisible on the primary theme. Every variant below moves it to --track (5.26 : 1 / 8.19 : 1).

The spec asks for one brand element and the screen has three. SCREENS.md §1: "centered wordmark on a slow-breathing gradient; nothing else." Current screen has a 112px mark, a wordmark, and a 150px rule carrying a second, smaller copy of the same wave — the motif twice, at two scales, within 100px.

Fixed already: the mark radius. It was r=45 in a 112 box (0.402 of the canvas) against Android 12's 0.3056 safe radius, so it would have been clipped as an adaptive icon. It's r=34 (0.3036) in all three variants.

What I want your eye on

A determinate progress indicator is not buildable as the code stands, and I nearly designed one anyway. I read src/appBootstrap.ts: bootstrapApp() awaits exactly one thing — bootstrapSession(). connectPlayer, connectSocket, startBiometrics and cold persistence are synchronous or fire-and-forget. So there is one real stage, not four. Variant B's restore line is therefore honest only as a time-based fill against a known p95, or it needs bootstrapSession instrumented to emit sub-steps (keychain read → refresh → profile). That's a dev task. If you pick B, I'll write it up as one.

How long is this screen actually up? The spec budgets ≤1.5s. If that's real, Variant A is right and an indicator is noise. If a cold start with a token refresh on a bad network can run several seconds, A is a frozen screen and B or C earns its place. I don't have a measured number and I'd be guessing.

The native bootsplash seam. Android/iOS show a baked bootsplash before React mounts. It bakes the mark at BREATH_OPACITY.rest = .45. Whatever you pick has to start at .45 on its first frame or the handoff pops. Variant A and C both do; B holds at .75 and would need its first frame adjusted.

Fonts. This file has to run offline, so it uses system faces. The real screen uses General Sans for the wordmark. Letterform and tracking will differ from what you see here; proportions and layout won't.
