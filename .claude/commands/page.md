THE RECORD — docs/design-v2/pages/$ARGUMENTS/
- gates.json is the index: per gate, an append-only list of entries {seq, agent, subject, verdict, pass, date, inputSha (all 40 chars), inputs, artefact, verdictFile, round}. The verdict files are the record and gates.json only indexes them. The latest entry per gate, agent and subject is the one with the highest seq; for the same inputSha a failing entry outranks a passing one. A verdict file is only ever added. Any commit that modifies or deletes one (`git log -m --diff-filter=MD --format=%H <target> -- docs/design-v2/pages/$ARGUMENTS/verdicts` non-empty, <target> as in the staleness rule) voids the record until I rule on it; my ruling names those commit SHAs, and a modifying or deleting commit that no ruling names still voids it.
- verdicts/<seq, 4 digits>-G<k>-<agent>-r<round>-<first 12 chars of inputSha>.md holds each verdict word for word. developer is the scribe (read-only agents cannot write). The orchestrator, never the scribe, diffs the committed file against the agent's returned message before the next dispatch, and any difference is re-scribed; a verdict file is re-scribed as a new file under the next seq whose entry names the mis-scribed seq, a mis-scribed entry never counts and never outranks another, and a committed verdict file is never edited. The same applies to every artefact taken from a verdict: charter.md, brief.md (one verbatim section per G1 agent, never merged or reordered) and spec.md. An authoring entry (G0 architect, each G1 agent, G4 designer) counts only after its author is re-dispatched at the commit that holds the artefact and confirms it is its own text. That confirmation is the counted entry and is not a review round. Commit single-line, e.g. "docs: P1 G4 verdicts".
- inputSha is the full page-branch HEAD, stated in the dispatch prompt together with the page worktree's absolute path. Dispatch, or present an owner gate, only when `git -C <worktree> status --porcelain` is empty and nobody is editing that worktree. Every verdict must quote the SHA and cite files under that path. Every returned verdict is recorded. One that does not quote the SHA, or that cites files outside the worktree, is recorded as failing ('no SHA' / 'wrong tree') and re-requested; a re-request never replaces a returned verdict. For a gate whose agent commits into its own inputs, the counted entry is taken in a closing dispatch at the HEAD after the work, which re-runs the gate's exit evidence from a clean tree.
- inputs, per gate, as full repo-root paths (D = docs/design-v2/pages/$ARGUMENTS): G0: D/row.md (the page's plan row, kept identical to the plan's table by a guard test) and docs/design-v2/registry/<ID>.md for each L1 ID the row cites (one file per ID). G3: G2's inputs + D/board/ (tracked, with the generated token stylesheet it renders). G4, G5, G6: G3's inputs + D/spec.md. G7: D/charter.md, D/brief.md, D/spec.md and the charter's CONTRACT paths (routes, DTOs, schemas and their tests). G8: per component, that component's own files, the token source and D/spec.md. It holds every file in the page entry's import closure that is not in the PAGE SLICE, plus the token source and generated tokens, the navigation files, package.json and the lockfile, and android/. At G13 the import closure is recomputed in a detached worktree of the PR head (`git worktree add --detach <tmp> H`, then `npx --yes madge --extensions ts,tsx --json <page entry>` inside it, first proven to see a planted import through the babel aliases; the worktree is removed afterwards), and a non-zero exit or a result that does not list the page entry voids G9–G12; any file in it that is in neither the PAGE SLICE nor the SHARED BASE voids G9–G12. gates.json and verdicts/ are never inputs.
- A verdict is STALE when `git -C <page worktree root> diff --quiet <inputSha> <target> -- <inputs> ':(exclude)docs/design-v2/pages/$ARGUMENTS/gates.json' ':(exclude)docs/design-v2/pages/$ARGUMENTS/verdicts'` exits non-zero. <target> is the page-branch tip during the pipeline and, at G13 and in /merge, the PR head SHA read with `gh pr view <n> --json headRefOid` after `git fetch origin`. <inputs> is what the inputs rule prescribes for that gate at <target>, with charter.md read at <target>, never only the inputs field the entry recorded: full repo-root-relative paths, no globs, never empty. Before an entry is recorded, `git -C <root> ls-tree -r --name-only <inputSha> <path>` must list at least one tracked file for every input; if one lists nothing, the entry is re-declared, not recorded. Any non-zero exit is STALE, including 128 for an unknown SHA. A stale verdict does not count. A verdict by compliance-auditor, regulatory-researcher or sentinel is also STALE when its date is more than 60 days before the check (the sentinel's shelf life, sentinel.md Axiom 4) or when a registry/<ID>.md it cites changed. It is re-affirmed against the re-fetched source.

RE-RUN RULES
- A fix re-runs the gate whose finding it fixes, then every gate, earlier or later, that the staleness rule marks stale; the rule decides, not judgement. A re-run caused only by staleness is a re-affirmation. Its dispatch carries the old and new inputSha and the output of `git diff --stat <old> <new> -- <inputs>`, and the agent either names that diff and states why it does not touch what its verdict judged, or reviews afresh. Evidence is never re-affirmed: G7 and G9 re-run their suites, G11 re-captures, and G12 re-judges the new captures, each at the new inputSha. The one exception is G12, which may be re-affirmed when every capture in the new G11 manifest is hash-identical to the one it judged. A G11 entry counts only if its manifest's commit SHA equals the entry's inputSha and the manifest records an empty `git status --porcelain`. A re-affirmation, and an evidence re-run caused only by staleness, is not a review round.
- Every finding cites a rule ID and a severity: P0 (contract, ethics, law, contrast), P1 (hierarchy), P2 (polish — never blocking). The rule ID is a CMP-, REG-, DEC- or QA- ID, or a DSN- design rule once ADR-0017 mints them in the L1 registry at V1; until then a design finding cites a spec.md section or key, a WCAG success criterion or a lint rule.
- At most two review rounds per gate, and at G8 a round is one designer review of every new component, presented together in the Design Lab, so the cap counts across all of them, not per component; after that the question comes to me as a DEC- entry.
- A systemic finding becomes a token or component change, then a sweep of every page already migrated; the staleness rule shows which of their gates re-open.
- A HALT is terminal until resolved. Never re-run a gate hoping for a different answer without new evidence, and never argue a verdict away.
- Changing the direction after G3 needs a superseding ADR.

REPORT after each gate, in one block: page, gate, verdict per agent, input SHA, artefact path, what is now stale, the next gate. Mark any work that passed through no agent. Stop at every owner gate, every HALT and every Pause & Guide.
