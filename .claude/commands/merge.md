Merge these approved PRs in this exact order: $ARGUMENTS. For each, in turn: 1) `git fetch origin`, then read its head SHA H with `gh pr view <n> --json headRefOid --jq .headRefOid`. 2) Confirm CI is green on H. 3) Check whether the PR changes any path covered by a design-v2 page's prescribed inputs (`gh pr diff <n> --name-only` against every page's prescribed inputs under /page's inputs and staleness rules, registry and D/ files included, read at H): a page PR, a /fix-bug PR, a token or component sweep, a backend contract change. If it does, confirm `git merge-base --is-ancestor origin/main H` (the PR already contains current main), and run the /page G13 check at H, required agent by required agent, for every page it touches; for a page already merged, only G7–G12 are re-checked. If the PR does not contain current main, stop and tell me. Main is merged into the page branch, never rebased, and G13 re-runs. If any required verdict is missing, failing or stale at H, stop and tell me. 4) Merge with `gh pr merge <n> --squash --delete-branch --match-head-commit H`, so a push after the check refuses the merge. 5) Read the squash commit S with `gh pr view <n> --json mergeCommit --jq .mergeCommit.oid`, fetch, and require `git diff --quiet H S` to exit 0. A non-zero exit on a step-3 PR means main moved and the merged tree is one no gate saw: stop and tell me. Re-fetch main before the next PR. An earlier merge in this batch makes every later step-3 PR fail the ancestry check until main is merged into it. Never merge one that isn't green or approved. Report H and S for each.
