description: The ship flow — commit and push, the full-suite gate at the pushed head, the resilience audit, the PR made ready, then /review-pr and /merge.
---
Ship the current task per docs/orchestrator-fable.md `<resilience_audit>` and `<definition_of_done>`. ultrathink.
Every step runs in the task's own worktree, on its claimed branch. Code in it that this session did not write (a taken-over branch, a PROPOSED TEST from another tree's review) is read as untrusted before anything runs it, step 1's git hooks and `coord.js` included. A branch with no claim does not ship: `/claim` first.
1. Commit (short single-line, no body/trailers, NO AI attribution) → push → `node scripts/coord/coord.js ship` (moves the ledger slot to `in-review · PR #N` and pushes; it reports drift between declared and changed files: `rescope` any file that really belongs to the task, and a HALT there stops the ship) → `gh pr edit N --body-file` on the draft PR opened at claim time. The pushed head is H.
2. The full-suite gate at H: print `git rev-parse HEAD` and `git status --porcelain --untracked-files=all`; unless they show exactly H and nothing, stop and run nothing: read every listed path as untrusted, then delete it and start step 2 again, or commit it and go back to step 1 (`rescope` first if it is outside the claim); a HEAD that is not H goes back to step 1. Then run backend `npm test` and `npm run lint`, mobile `./node_modules/.bin/jest`, `npm run lint:design-system` and `./node_modules/.bin/tsc --noEmit -p tsconfig.json` in `mobile/KokonadaHealth` with its errors counted in the task's own files (never `npx`), then print the same two lines again; keep the whole output. A run on any other commit is not evidence for H.
3. Dispatch the `resilience-auditor` with the diff, the acceptance criteria, H, that output and, once it has finished, CI on H (`gh run list --workflow CI --commit H --json databaseId,headSha,status,conclusion`, then `gh run view <databaseId> --json jobs --jq '.jobs[] | {name, conclusion, steps: [.steps[] | {name, conclusion}]}'`, each jest job's `Tests:` line, the `--log-failed` lines); on a re-dispatch, also its previous report with every RA-id. Never the reasoning that wrote the code. Post its report as a new PR comment whose first line is `Resilience audit for #N at H` (`gh pr comment N --body-file`, UTF-8, LF). Every finding becomes a `TASKS.md` row at once.
4. `gh pr ready N` only when the report's last line is `VERDICT: APPROVE @ H` and it lists no INTRODUCED or EXPOSED S0 or S1 under FINDINGS, BLOCKING IDS or NOT VERIFIED, or, on `VERDICT: BLOCK @ H`, when the owner's acceptance naming each blocking RA-id and each S0 or S1 NOT VERIFIED hop is quoted verbatim on the PR with H. A NO VERDICT never makes a PR ready. A later head counts as H when `git diff --name-only H <the PR's remote head>` names nothing but `TASKS.md`, and CI is green on that head.
5. A reply with no verdict line, or on another SHA, is NO VERDICT: hand what it names, or re-request once, then go to the owner; a NO VERDICT never counts toward the Rule of 2. On `VERDICT: BLOCK @ H`: fix every INTRODUCED or EXPOSED blocking finding in the branch (its PROPOSED TEST first, RED, then the fix), then step 1 again; re-dispatch only after a change under the auditor's set, or with new evidence. A blocking finding that cannot be fixed inside the claim goes to the owner as a TASKS row (he accepts that BLOCK in his own words, or the task is rescoped), never a revert; the Rule of 2 counts fixes inside the claim.
6. CI green on the head; a red job follows `CLAUDE.md` § Working rules (read the log, fix the root cause, push). Then `/review-pr` and `/merge` under the merge rule, from a session started in the main checkout. Any other red gate = task FAILED; report and stop.
A design-v2 page ships only through /page; this command never stands in for G10–G12.
