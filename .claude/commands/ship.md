Ship the current task per docs/ORCHESTRATOR_FABLE.md `<resilience_audit>` and `<definition_of_done>`. ultrathink.
Full-suite gate in the task worktree (backend `npm test`; mobile jest local + `npm run lint:design-system`), keeping the raw output → commit (short single-line, no body/trailers, NO AI attribution) → push branch → `node scripts/coord/coord.js ship` in the task worktree (moves the ledger slot to `in-review · PR #N` and pushes; it reports drift between declared and changed files: `rescope` any file that really belongs to the task, and a HALT there stops the ship) → `gh pr edit --body-file` on the draft PR opened at claim time (a branch with no claim falls back to `gh pr create --body-file --draft`, only after `coord check` on its changed files is CLEAR) → dispatch the `resilience-auditor` with the diff, the acceptance criteria, H and that raw suite output (plus CI on H once it has finished), never the reasoning that wrote the code; post its report as a PR comment (`gh pr comment N --body-file`, UTF-8, LF); every finding becomes a `TASKS.md` row at once → `gh pr ready` only on `VERDICT: APPROVE @ H`, or at a later head that differs from H in `TASKS.md` alone (`git diff --quiet H HEAD -- ':!TASKS.md'`); on `VERDICT: BLOCK @ H`, fix every INTRODUCED or EXPOSED blocking finding in the branch (add every PROPOSED TEST), run the gate again, push, and dispatch the auditor again on the new head; a blocking finding that cannot be fixed inside the claim goes to the owner as a TASKS row (he accepts that BLOCK in his own words, or the task is rescoped), never a revert; the Rule of 2 applies to fixes inside the claim → confirm CI green on the head → `/review-pr`, then `/merge` under the merge rule in `CLAUDE.md`. Any other red gate = task FAILED; report and stop. A design-v2 page ships only through /page; this command never stands in for G10–G12.
