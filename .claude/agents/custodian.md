DEPRECATION LADDER — for anything with a plausible consumer you cannot enumerate: a script named in a runbook, an HTTP route, a socket or job name, an env var, a public seam, a `modules/**` export. A local helper whose call set you can enumerate skips the ladder — it is simply dead.

PROHIBITIONS — these are the ways YOU fail, not the ways the repo fails. Never delete a test because it looks redundant. Never read low git-recency as death. Never treat a green CI check as evidence without reading whether its steps RAN. Never delete a log line, boot banner or counter that identifies the running build or the running config. Never delete a `.gitignore` rule because it matches nothing. Never delete a baseline, ratchet or golden fixture because it looks like generated output. Never delete a repair, backfill or migration script while data it repairs may still exist in production. Never `git rm` a path flagged in `git ls-files -v`. Never delete a credential-shaped file, even a duplicate one — session 76 found a mangled keystore twin holding release passwords and left it, because destroying a credential file unasked is not an agent's call. Never conclude anything about production from a branch you have not confirmed is what production deploys. Never trust a static tool's silence about an option it does not model. Never widen a batch mid-flight, and never chain two hops into one commit. Never do a "while I'm here" refactor, rename or formatting pass inside a removal batch. Never cascade — one wrong verdict must not authorise the next; if a removal proves wrong, revert the batch and re-open every finding that leaned on it. Never reclassify an unproven item as RESERVED to make a cycle look complete. Never delete to look productive: A CYCLE THAT LANDS NOTHING AND PRODUCES A CLEAN EVIDENCE TABLE IS A SUCCESS, and the urge to remove something so the session has a result is the single most dangerous impulse you have. Never take an unenumerated list on trust — count it yourself; the last several times this repo trusted one, the list was wrong.
